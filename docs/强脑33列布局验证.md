# BrainCo SDK 2.1.2 的 33 列布局验证与修复

日期：2026-10-31。相关真机日志：brainco-check-20261031-121351-745565，配置回读/启动成功后报 Unexpected BrainCo channel layout: (10, 33)。

## 已确认的布局

使用当前安装的 SDK 2.1.2 二进制做离线解析验证，而非仅模拟 get_eeg_buffer 返回值。二进制 SHA256 与采集电脑日志一致：

`5fcde9509ef0c22407c85ffd05d0795b6491a68eb9959939d2dcd5fafc8c8c6b`

测试将已知时间戳和 32 通道各不相同的有符号 ADC 数值编码为合成设备数据包，直接交给 SDK 的 MessageParser.receive_data，再调用真实 get_eeg_buffer 读取。测试包仅用于本机离线解析，不发送给帽子，生产代码仍完全使用 SDK 公共接口。

结果：每行是一个样本；第 0 列对应协议 EegSample.timestamp，列 1～32 对应全部 32 路 EEG。合成 10 个样本得到 (10, 33)。正负 ADC 数值逐通道匹配 SDK 的微伏换算：4.5e6 / gain / 2^23。转换成 NeuroScope 数据块后为 (32, 10)，第一个、最后一个 EEG 通道均保留，无列偏移。

SDK 返回的时间戳经过 float32 精度处理。例如输入 123456789，会暴露为 123456792；相邻时间戳可能变成相同值。因此不通过该列去重，不据此宣称硬件时钟精度或检测丢包。设备时间戳的物理单位未经真机确认，不当作 Unix 秒或 LSL 时间。

## 实施

- BrainCoAcquirer 在 SDK 2.1.2 下采用配置回读启动流程，配置一致时不重复写入。
- 兼容缺少 mode 的配置应答时保留原错误，并要求独立读取确认配置；启动命令异常仍停止。
- 对 N×33 的原始缓冲区分离第 0 列与其余 32 列。N=32 或 33 时也按 SDK 的样本行布局处理，不用维度大小猜转置。
- 回调仅统计对应样本数并通知有数据；正式数据只从 get_eeg_buffer(take, True) 读取，避免回调与轮询重复记录。
- 设备时间戳通过 brainco_device_timestamps 附加数组写入正式原始记录，诊断 NPZ 中保存为 device_timestamps；无该字段的旧输入不会伪造设备时间。
- 实验时间轴继续采用累计样本数/采样率，保留原有 loss_detection 限制声明。
- 修改仅作用于 BrainCo 分支，SDK 文件未修改。

## 验证

自动化测试：tests/acquisition/test_brainco_native_layout.py。

覆盖真实 SDK 解析、通道顺序及数值、时间戳分离、浮点舍入、不按重复时间戳删样、回调与轮询不双计数、连续块样本索引，以及 NativeRecorder 写入后 EEG 与附加时间戳逐值回读。也覆盖 1/10/32/33/250 行、8/32 通道选择、错误列数与非有限值。

这些是离线 SDK 和文件链路验证，不能代替真实帽子的长期运行、信号质量、实际范式打标和正式实验验收。

## 真机采集成功后的元数据与触发记录修正（2026-10-31）

- SDK 2.1.2 直连启动成功后，EEG 元数据使用 uV，保留原数值，不重复转换；其他来源不套用此单位。通道位置及参考仍须按实物确认。
- 记录起点使用实际保存的第一个非空 EEG 块的样本索引；启动请求时的索引另存为 requested_source_sample_offset。空 EEG 块中的触发记录不改变起点。
- 界面分别显示 Trigger 开启确认状态、连接以来接收条数；超时仍保留原因，不能将开启确认等同于物理同步成功。
- BrainCo 原始触发仍保存在 raw/chunks.jsonl 的 brainco_trigger_events_json 字段。报告读取这些字段并汇总本段条数，生成 analysis/<generation>/brainco_triggers.json；交付导出生成 delivery/brainco_triggers.json，并将证据携带到交付包的 session.json。
- event_seq 不是范式码，sample_counter 与保存 EEG 的映射尚未验证；读取和导出不会生成虚假的硬件对齐结果。
- 旧记录只读兼容，不自动改单位、起点或原始样本；重新分析旧记录不能凭空补出当时没有保存的同步状态。

## 默认通道名称

SDK 2.1.2 直连默认按包内 Channel Layout 文档命名；有明确 channel_names / channel_types 的设备配置时采用该配置。列表严格对应 SDK EEG 列的原始顺序，不重排或缩放样本：

`FP1, FP2, F3, F4, F7, F8, Fz, C3, C4, Cz, P3, P4, P7, P8, Pz, O1, O2, T7, T8, FC1, FC2, FC5, FC6, CP1, CP2, CP5, CP6, FT9, FT10, TP9, TP10, IO`

IO 在 SDK 文档中标为 reference，默认类型为 misc，原始值完整保存。此命名不构成实际采集参考接法的确认；profile_confirmed 仍由已核实的设备配置决定。LSL 及其他设备不会套用该表。
