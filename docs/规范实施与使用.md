## 安装和启动

Windows x64 / Python 3.12。安装 uv 后运行 `setup-workbench.ps1`，使用锁文件创建项目 `.venv`；公司 SDK wheel 需随部署材料提供并校验。可用 `-SkipOmni` / `-SkipBrainCo` 跳过未使用的设备依赖。启动批处理只使用 `.venv`，不回退到 conda 或 `.venv312`；旧环境不自动删除。

```powershell
uv sync --locked --extra desktop --extra brainco --extra omni
uv pip check --python .venv/Scripts/python.exe
uv run --no-sync python -m neuroscope_eeg.desktop.app
```

工程保持现有包布局，但 uv 不安装项目本身，直接从仓库源码运行。不要使用旧 wheel 或 requirements 文件建立另一套环境。更改依赖时更新 pyproject.toml 和 uv.lock；实验机不自行升级。

## 实验信息

按用户指定，SSVEP 的代码及唯一名称均为 `SSVEP-20261030`，运动想象均为 `MI-20261030`。选择对应范式时自动填写，日期保持固定；其他范式不自动分配编号，已有手填代码在本次窗口内切换回来时保留。此次设置不改变试次、时长或刺激内容，也不表示已验证外部平台登记。

1. 选择范式，进入实验准备，点击“建立 / 编辑实验信息”。
2. 填写完整名称、固定唯一名称和实验目的/任务简介。唯一名称由 1–6 位大写字母、短横线和有效建立日期组成，如 `SSVEP-20261022`；这里是格式示例，不是已经分配的编号。
3. 保存后形成 `experiments/<范式标识>/metadata.toml`，本范式后续采集自动读取。切换范式后读取对应文件；不同范式不能在编辑器中重复使用同一唯一名称。
4. “范式代码”仍是独立的业务字段，按实际已登记代码填写。程序无法确认平台中是否真实存在该代码。

没有本地信息时，模拟/回放使用固定的专用测试身份；真实完整采集会要求先建立信息。快速演示不要求正式信息。已有唯一名称在编辑器中保持稳定；确需修订或建立另一实验，应保留旧文件与历史记录，并另行确定配置映射，不能直接改写历史数据。

本项目采用“每种范式独立元数据”的实现选择；这不是模板明确规定的多范式组织方式。元数据可版本管理，不包含被试个人信息。

## 设备配置与 EDF

设备 JSON 的未知字段、非法类型、非法工频、量程上下限等会报错；SSVEP/MI 协议未知字段也会报错。配套示例仍保持 `confirmed=false`，不能照抄成真实设备配置。

本机记录导出需在已确认配置中补充：

| 字段 | 内容 |
| --- | --- |
| physical_min / physical_max | 两个等长数值列表，覆盖所有实际保存通道，包括辅助通道；单位及顺序与 channel_units/channel_names 相同 |
| range_evidence | 实际型号、增益/档位、文档或测量依据，说明范围来源 |

范围必须来自已核对设备信息，不根据本次观测极值猜测。缺失范围、数据越界或 EDF 头回读不一致时不发布交付包，也不裁剪或扩大范围。原始记录和独立报告保留。模拟使用明确标注的模拟编码范围，不将其作为任何设备规格。外部 EMOTIV EDF 保留原始文件头并核验哈希，仍需确认通道类型、时区和事件对齐。

`adc_rails_uv` 是分析中判定削顶所需的硬件轨限，不能因为配置了 EDF 编码范围就自动认为二者等同。

## 事件与追溯

事件表继续以 onset、duration 为前两列，增加原始标签、试次、条件、练习标记、组号和上下文 JSON，并在同名 events.json 中解释。这些是 NeuroScope 扩展，不自称尚未提供的公司标准字段。

- guided 阶段有实际后续边界时，可保存由两次样本游标估算的区间，类型为 `software_phase_interval`；仍注明未经校准。
- 瞬时事件或缺失结束边界时不猜时长；保留 `phase_transition` 和零时长。
- 显式对齐文件提供区间时标记 `aligned_interval`；不把计划时长当作实测时长。
- 任务记录的种子、条件顺序和计划参数保留在原始事件上下文中。

每段 Records 记录增加 `provenance.json`：Git 提交/修改状态、源码和依赖锁哈希、实际依赖版本、素材内容哈希。没有 Git 时仍保存文件哈希。报告输入校验也包含此文件。
