# SSVEP 显示调度与检查

2026-10-31 更新。适用于新启动的 SSVEP 实验，默认每试次只有当前目标闪烁，另七块保持暗色；八目标同时闪烁模式仍可选择。

## 调度方式

- 请求 OpenGL `swapInterval=1`，由一次新画面的 `frameSwapped` 回调请求下一帧。不再用 `round(1000/刷新率)` 毫秒定时器控制闪烁，避免 75 Hz 被取整成 13 ms 等系统性调度偏差。
- 8–15 Hz 使用按显示时刻采样的 50% 占空比方波，不把每周期长度取整为固定帧数。相位以首个闪烁画面交换时刻为起点，使用 `perf_counter` 和下一次画面交换的预测时刻。偶发延迟后按经过时间继续相位，不因少画几帧而累计降低目标频率。
- 闪烁中的文字、边框和背景缓存复用；准备阶段预建缓存，分辨率或缩放改变时重建。每帧只更新目标亮度。
- 100 ms 定时器只用于检查刷新是否停滞；超过 250 ms 未收到新画面的交换回调时再次请求重绘。它不产生闪烁帧、不推进闪烁阶段。
- 只有已绘制画面中的阶段事件才在交换回调中确认，绘制后才创建的事件等待下一幅画面。

## 异常处理

**显示时序异常只记录，不自动停止、暂停实验，不弹窗打断。** 手动停止、Esc 退出、正常流程完成等行为保留。

软件逐帧统计交换间隔，并单独保存每个试次的闪烁画面数、最大间隔、异常间隔数及估计跳过的显示时隙。异常间隔定义为小于系统报告刷新周期的 0.5 倍，或大于 1.5 倍。计数包括最后一幅闪烁画面到下一阶段画面的间隔；中途手动停止的闪烁段标为未完整结束。

数据位置：

1. 原始记录 `events.jsonl` 的 `stop.payload.display_timing.ssvep_frame_clock`。
2. 报告分析目录中的 `assessment.json` → `protocol.display_timing.ssvep_frame_clock`。
3. 同目录的 `ssvep_frame_timing.csv`：逐试次交换时序；`display_timing.csv`：按阶段汇总的回调时序。报告也会说明异常次数。

`scheduler=frame_swapped_v1`、`anomaly_action=record_only` 标识此版本行为。刷新恢复请求数量 `recovery_requests` 不等于实际丢帧数；新的 100 ms 看门定时器回调频率也不等于屏幕刷新率。

## 验证边界

`frameSwapped` 是 Qt 画面交换证据，不是光电测量。显卡驱动、桌面合成、显示器和后台负载仍可能造成延迟，因此不能承诺任意实验室电脑绝不丢帧。软件记录始终保留 `physical_onset_verified=false`。

频率自动测试覆盖 59.94、60、75、120、144 Hz 等刷新条件、单目标与同时闪烁模式，以及报告刷新率与交换速率不同的情况；流程测试覆盖卡顿后继续、刷新恢复、重复交换信号和阶段事件归属。这些检查能验证软件生成逻辑，实验室屏幕真实发光频率和硬件标记延迟仍需在实际设备上测量。

本次更新不更换 EEG SDK，不修改设备采集、硬件事件发送协议或旧记录。
