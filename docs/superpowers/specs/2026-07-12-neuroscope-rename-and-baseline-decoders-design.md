# NeuroScope 重命名与即时基线 Decoder 设计

## 1. 目标

将现有项目完整重命名为 **NeuroScope｜多范式脑电可视化工作台**，并为 SSVEP、运动想象、视觉目标觉察、注意力和情绪任务提供开箱即用的即时基线 decoder。

本阶段的目标是让 Windows 采集电脑接入博睿康 Neuracle 或强脑 BrainCo 后，可以立即看到可解释的趋势和粗略结果。即时基线结果不等同于经过受试者数据验证的正式模型结果。

## 2. 命名

统一采用以下命名：

- 产品名：`NeuroScope`
- 中文副标题：`多范式脑电可视化工作台`
- GitHub 仓库建议名：`neuroscope-eeg-workbench`
- Python 分发包名：`neuroscope-eeg-workbench`
- Python 导入包名：`neuroscope_eeg`
- 环境诊断命令：`neuroscope-doctor`
- 诊断包命令：`neuroscope-bundle`
- 默认诊断包：`neuroscope-diagnostic.zip`
- 交付压缩包：`neuroscope-eeg-workbench-<日期>.zip`

代码、测试、README、页面标题、诊断文本、文档文件名和内部路径中的 `MI Control`、`mi-control`、`mi_control` 均需迁移。旧的 `streamlit_app.py` 和 `realtime_eeg_viewer.py` 继续作为兼容启动入口，但其中的产品描述改为 NeuroScope。

本地工作区的顶层文件夹由用户在文件系统中改名，不由 Git 跟踪。交付压缩包解压后的根目录使用 `neuroscope-eeg-workbench`。

## 3. 结果语义

界面中的每个结果必须标明来源，避免把实验标签、简单指标和模型预测混为一谈：

- `实验记录`：实验程序已知的信息或受试者报告。
- `即时基线估计`：无需预训练或仅使用短时个人基线的经典算法结果。
- `已训练模型`：从模型文件加载并通过元数据兼容性检查的预测结果。
- `尚未解码`：当前数据、通道或事件不足以产生结果。

结果卡至少显示：结果名称、估计值、置信度或强度、来源、所用时间窗和限制说明。信号质量不合格时，不给出确定类别，只显示“信号质量不足”。

## 4. 统一 Decoder 接口

新增独立 decoder 层，不把分类逻辑继续堆入范式页面。每个 decoder 接收：

- 预处理后的 EEG 时间窗；
- 采样率、通道名和设备元数据；
- 当前事件及范式配置；
- 可选的个人基线或已训练模型。

统一返回：

- 预测或连续分数；
- 置信度或响应强度；
- 结果来源；
- 所需但缺失的通道、事件或配置；
- 可供界面展示的关键特征。

已训练模型必须带有模型清单，至少记录范式、类别、通道顺序、采样率、预处理参数和版本。元数据不兼容时拒绝加载并给出可操作提示。

## 5. 各范式即时基线

### 5.1 SSVEP

使用滤波器组典型相关分析思路，对配置的刺激频率及其谐波进行匹配，输出最可能的刺激频率、各候选频率得分和置信度差值。

- 输入要求：至少一个枕区或后部通道、刺激频率列表、约 1 至 3 秒数据。
- 无频率列表时：只显示频谱峰值，不输出 SSVEP 类别。
- 后续模型：允许加载受试者模板或更完整的 FBCCA 参数。

### 5.2 运动想象

即时模式使用感觉运动区左右通道的 mu/beta 频段功率变化和侧化指数，输出 `左侧趋势`、`右侧趋势`、`静息/不确定`。

- 输入要求：优先使用 C3、C4 和 Cz；缺少标准通道名时允许用户映射。
- 无个人基线时：结果标为低置信度趋势。
- 有短时个人基线时：使用相对 ERD/ERS 改善稳定性。
- 后续模型：采集带标签试次后使用 CSP 特征和 LDA 分类器。

### 5.3 视觉图像与目标觉察

必须严格区分实验真值和 EEG 估计：

- `image_category`：受试者正在观看的图像类别，属于实验记录。
- `target_present`：目标是否实际出现，属于实验记录。
- `seen_reported`：受试者是否报告看见，属于实验记录。
- `visual_response`：枕区视觉响应强度，属于即时基线估计。
- `target_response`：目标事件后的 ERP/P300 候选响应强度，属于即时基线估计。

在没有带类别标签的个体训练数据时，不从 EEG 猜测任意图像类别。界面显示“图像类别尚未解码”，同时继续记录真实类别，以便之后训练图像类别模型。

### 5.4 注意力

使用 theta、alpha、beta 相对功率和个人短时基线生成 0 至 100 的注意力趋势分数。

- 首选流程：开始任务后采集约 20 至 30 秒个人基线。
- 没有个人基线时：显示原始注意力相关特征和低置信度估计。
- 分数只用于当前受试者、当前会话内比较，不作临床解释。

### 5.5 情绪

使用额叶 alpha 不对称和 beta/alpha 激活度，输出粗略的效价倾向、唤醒趋势及四象限展示。

- 优先通道：F3、F4，并结合可用的额区通道。
- 缺少左右额区成对通道时：不输出效价倾向。
- 输出始终标为科研趋势，不作心理或医疗诊断。
- 后续模型：使用带自评标签的个体数据训练效价/唤醒分类器。

## 6. 界面调整

保留已确认的 A 版任务工作台布局，在“范式分析”中增加：

- 当前 decoder 名称和运行模式；
- 即时结果卡；
- 结果来源徽标；
- 信号质量与通道要求；
- 关键特征图；
- “未标定，仅供快速观察”的明确提示；
- 模型加载状态和兼容性错误信息。

视觉任务表单继续保留图像类别、目标是否出现、是否报告看见三个字段，并在页面上放入“实验记录”区域，不与 decoder 预测并列成同一种结果。

## 7. 数据流

设备或文件数据依次经过：

1. 统一采集层；
2. 通道、采样率、单位、时间戳和事件标准化；
3. 环形缓冲与信号质量检查；
4. 通用预处理；
5. 范式事件切窗；
6. 即时基线 decoder 或已训练模型；
7. 结果卡、特征图和实验记录；
8. 会话结果导出。

## 8. 错误处理

- 设备或 SDK 不可用：保留明确连接状态和解决提示。
- 缺少关键通道：说明需要哪些通道，并降级为特征展示或尚未解码。
- 时间窗不足：等待更多数据，不输出随机类别。
- 信号质量不合格：禁止确定性预测。
- 模型不兼容：列出通道、采样率或预处理差异，拒绝静默运行。
- decoder 内部错误：不中断采集会话，页面显示当前范式分析失败。

## 9. 验证标准

### 9.1 Mac 本地验证

- 所有自动化测试通过；
- 静态检查通过；
- 模拟源可覆盖五类范式的即时结果或明确降级状态；
- NPZ 回放可重复产生相同结果；
- Streamlit 页面启动且没有界面异常；
- 全仓库不再出现面向用户的旧产品名或旧包路径。

### 9.2 Windows 采集电脑验证

- Python 3.12 环境可以安装新包；
- `neuroscope-doctor` 能报告 SDK 和依赖状态；
- 博睿康 JellyFish 实时转发可以连接并显示数据；
- 强脑 SDK 可以发现或连接设备并显示数据；
- 每个范式可显示即时基线结果、降级说明或尚未解码状态；
- 诊断包可以生成并回传排查。

Mac 端验证不能替代真实硬件验收。公司 GitHub 上传和推送仍需用户明确授权。
