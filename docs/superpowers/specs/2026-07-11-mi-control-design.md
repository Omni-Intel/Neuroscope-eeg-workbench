# MI Control 独立 EEG 工作台设计

日期：2026-07-11
状态：已完成对话设计确认，等待书面规格复核

## 1. 目标

将现有 MI Control 原型整理为可独立安装、可验证、适合公司 GitHub 的本地 EEG 工作台，同时支持：

- 博睿康 Neuracle / JellyFish 实时数据；
- 强脑 BrainCo EEG Cap 实时数据；
- 模拟数据和真机诊断包回放；
- 通用 EEG 实时监控与信号质量分析；
- SSVEP、运动想象、视觉图像类别解码、目标觉察、注意力和情绪分类；
- macOS 开发与 Windows 真机采集的跨机器验证流程。

未经用户明确确认，不创建公司 GitHub 远端、不推送、不上传。

## 2. 核心原则

1. **独立仓库**：运行时不得依赖另一项目的绝对路径。可迁移 `oi-mi` 中必要且兼容许可的采集实现，但应保留来源说明和相应测试。
2. **统一数据契约**：设备差异在采集层消化，后续缓冲、质量检测、范式和界面只处理统一格式。
3. **证据优先**：没有经过验证的模型时，只展示可解释特征，不生成看似真实的分类结果。
4. **不静默降级**：通道、单位、采样率、时间戳、事件或模型不兼容时，明确阻止相关分析并解释原因。
5. **跨平台复现**：macOS 和 Windows 各自创建 Python 3.12 虚拟环境，不复制或提交虚拟环境。

## 3. 当前原型与缺口

当前仓库包含一个 Matplotlib 实时查看器和一个 Streamlit 控制页面。模拟流能够生成图像；博睿康与强脑适配器可被构造，但本机没有 JellyFish 转发、BrainCo SDK 或真机，不能据此声称真机已跑通。

现有主要缺口：

- 强依赖本机 `/Users/mac/Documents/GitHub/oi-mi`；
- 没有正式包结构、自动测试、设备诊断包或版本化配置；
- 32 导模式的实际通道布局未建模，SSVEP 通道缺失时会退回全部通道；
- 时间戳、事件、单位、掉包、阻塞和重连没有统一健康模型；
- 目前只有通用频谱和基础 SSVEP 展示，其他范式尚未成为独立模块；
- 界面把全部配置堆在侧栏，窄窗口易拥挤，运行状态和错误边界不够清楚。

## 4. 总体架构

```text
设备或文件
  -> 统一采集层
  -> 通道、采样率、单位、时间戳、事件标准化
  -> 环形缓冲与信号质量监控
  -> 通用预处理
  -> 范式插件
  -> Streamlit 任务工作台与结果导出
```

建议仓库结构：

```text
mi_control/
  acquisition/       # 统一接口与各设备适配器
  core/              # 数据契约、缓冲、事件、会话和健康状态
  preprocessing/     # 通用滤波、参考与伪迹标记
  paradigms/         # 范式插件及可选解码器
  diagnostics/       # 环境检查、真机探测和诊断包验证
  ui/                # Streamlit 页面与组件
  io/                # 回放、记录和导出
tests/
  unit/
  replay/
  ui/
docs/
```

每个目录只承担一种职责，设备 SDK 不能直接进入界面或范式代码。

## 5. 统一数据契约

### 5.1 SourceMetadata

至少包含：

- `source_id`、设备类型和设备标识；
- 实际采样率；
- 通道名、通道类型、通道顺序和单位；
- 设备提供或用户确认的电极布局；
- SDK、固件和适配器版本（能够取得时）。

### 5.2 EEGChunk

包含：

- `data`：`float32`，形状固定为 `(channels, samples)`；
- 标准化后的数值单位，默认 EEG 使用 `uV`；
- 每个样本的时间戳或可证明连续的样本索引；
- 单调递增的块序号；
- 当前数据质量和掉包信息。

设备原始单位必须由适配器显式转换并记录换算关系。无法确认单位时，允许显示原始波形，但禁止输出依赖绝对幅值的指标。

### 5.3 Event

包含事件时间、名称、数值编码、来源和结构化载荷。事件时间必须可映射到 EEG 样本。视觉任务的事件至少记录：

- `stimulus_id`；
- `category`；
- `target_present`；
- `seen_reported`；
- 反应键与反应时；
- 刺激计划时间和实际呈现时间（能够获得时）。

`target_present` 与 `seen_reported` 是两个不同标签，不得互相替代。

## 6. 采集层

统一采集接口负责启动、停止、增量读取、元数据、健康状态和可选阻抗检查。

### 6.1 数据源

- **SimulatedSource**：生成可重复的基础 EEG、SSVEP、运动想象 ERD/ERS 和 ERP 测试信号。
- **ReplaySource**：读取诊断包或受支持的 EDF/BDF/NPZ 文件，以真实时间或加速模式回放。
- **NeuracleSource**：连接 JellyFish TCP 转发，解析实际通道和事件；不得假定固定 64 导或固定 1000 Hz。
- **BrainCoSource**：通过 `bc-ecap-sdk` 发现或连接设备，使用设备支持的采样率和通道配置，并暴露 SDK 能力与限制。

BrainCo SDK 作为可选设备依赖；基础模拟、回放和博睿康功能不因其缺失而无法安装。

### 6.2 连接状态

设备状态为：`unconfigured`、`connecting`、`streaming`、`degraded`、`reconnecting`、`failed`、`stopped`。

- 短暂断流进入 `reconnecting`，使用有限次数、带退避的自动重连；
- 重连期间停止新推理，但保留已采集数据和完整日志；
- 达到重试上限后进入 `failed`，安全停止并允许导出诊断；
- 参数改变前必须停止当前会话，避免旧工作线程继续运行。

## 7. 缓冲、预处理和信号质量

环形缓冲维护固定时长数据，并保证线程安全、通道数一致和块顺序可审计。

通用预处理只提供范式可组合的基础步骤：

- 去均值或公共平均参考；
- 可配置工频陷波；
- 可配置带通；
- 非有限值、平直通道、削顶、异常幅值和高频噪声标记。

实时质量页面至少展示：

- 实际采样率和刷新延迟；
- 掉包、重复块、时间戳倒退和缓冲积压；
- 每通道幅值、方差、工频污染和接触质量；
- SDK 支持时的真实阻抗；
- 当前可用于所选范式的通道集合。

质量检测给出数据状态，不擅自修复或隐藏原始数据。

## 8. 范式插件

每个插件声明：所需通道或区域、采样率范围、窗口长度、所需事件、预处理步骤、特征面板和可选模型契约。插件启动前验证输入条件。

模型状态分为：

1. 未加载：只显示信号特征；
2. 不兼容：阻止推理并列出通道、采样率、标签或版本差异；
3. 已验证：显示预测、置信度、模型版本和输入窗口。

### 8.1 SSVEP

- 枕区频谱；
- 基频和谐波 SNR；
- CCA/FBCCA 分数；
- 目标置信度与跨窗口稳定性；
- 刺激频率、刷新率和事件对齐信息。

缺少配置的枕区通道时必须报错，不退回全部 EEG 通道。

### 8.2 运动想象

- C3/Cz/C4 及邻近运动区波形；
- mu/beta ERD/ERS；
- 时频图和头皮分布；
- 使用经校准模型时的左手、右手、脚或静息概率；
- 受试者、校准日期、模型和类别定义。

### 8.3 视觉图像任务

包含两个独立输出：

- 图像类别多分类，例如人脸、物体和场景；
- 目标觉察二分类，预测受试者是否报告看见目标。

页面展示刺激时间轴、ERP/P300、类别平均响应、目标与非目标差异、地形图和可选模型结果。没有行为报告时，只能分析目标是否呈现，不能把它命名为“是否看见”。

### 8.4 注意力

- 持续注意任务事件和行为表现；
- alpha/theta/beta 等预先定义特征及趋势；
- 有标注模型时的注意状态结果；
- 指标定义、窗口和参考基线。

单一频段比值不得直接包装为通用注意力分类器。

### 8.5 情绪分类

- 效价和唤醒标签；
- 额区 alpha 不对称及预先定义频段特征；
- 时间趋势和可选分类结果；
- 数据集、个体校准和模型版本。

所有情绪结果标记为科研指标，不作医疗或心理诊断。

## 9. 界面设计

采用用户选择的 A 方案“任务工作台”。

### 9.1 固定区域

顶部持续显示设备、采样率、通道、连接状态、记录状态和严重警告。左侧只保留：

- 数据源和连接参数；
- 范式；
- 受试者与会话；
- 开始、停止和诊断操作。

### 9.2 主工作区

主区使用四个稳定页签：

- **实时监控**：波形、频谱、频段和基础地形图；
- **信号质量**：设备健康、通道质量、延迟和掉包；
- **范式分析**：由所选插件提供内容；
- **记录**：事件时间轴、文件、会话摘要和诊断导出。

高级连接和分析参数放入折叠区域或设置页，不与日常启停操作混在一起。界面必须在常见笔记本宽度下不截断标题和关键按钮。

## 10. 跨 Mac/Windows 验收

### 10.1 macOS

macOS 负责：

- 模拟和文件回放；
- 算法单元测试；
- 界面冒烟测试；
- Windows 诊断包验证；
- 不依赖硬件的持续集成。

### 10.2 Windows 采集机

Windows 使用 Python 3.12 独立虚拟环境。环境检查覆盖：

- Python 与虚拟环境；
- `bc-ecap-sdk` 及必要科学计算依赖；
- JellyFish 主机和端口；
- BrainCo 设备发现或手工地址；
- 可选 trigger box 串口；
- 项目版本和配置摘要。

博睿康需要人工开启 JellyFish 转发；强脑需要 SDK 和网络可发现性。程序应检测并给出操作提示，但不假装能够替代这些外部步骤。

### 10.3 诊断包

每次真机探测生成一个可传回 Mac 的诊断包，默认包含：

- 脱敏配置和版本；
- 元数据与通道表；
- 采样率、掉包、时间戳和质量摘要；
- 日志和界面截图；
- 用户明确允许时的一小段脱敏 EEG 回放数据。

诊断包不包含姓名等直接身份信息。只有真机采集和诊断包回放都通过，设备才能标记为“已验收”。

## 11. 测试策略

### 11.1 自动测试

- 缓冲裁剪、并发读取和数据形状；
- 单位、时间戳、事件映射和通道配置；
- 频谱、频段、SSVEP、ERD/ERS 和 ERP 合成信号；
- 模型兼容性检查和无模型状态；
- 设备适配器的模拟 SDK/Socket 测试；
- 断流、重连、参数变化和安全停止；
- 诊断包生成、脱敏和回放；
- Streamlit 启动、停止、错误、范式切换和常用窗口宽度。

### 11.2 真机验收

博睿康和强脑分别完成至少 10 分钟稳定性运行，并证明：

- 通道顺序与所选电极布局一致；
- 实际采样率相对配置误差不超过 1%；
- 时间戳不倒退；
- 没有未恢复断连或未处理异常；
- 停止后设备和工作线程能够释放；
- 界面持续刷新且记录文件可回放。

掉包率作为诊断指标持续记录；最终阈值应根据设备转发机制和真实基线确定，不用模拟数据臆造统一阈值。

## 12. 分阶段交付

1. **基础平台**：正式包结构、数据契约、模拟/回放、质量监控、任务工作台和自动测试。
2. **设备独立化**：迁移并测试 Neuracle 与 BrainCo 适配器，移除 `oi-mi` 路径依赖，完成 Windows 诊断命令。
3. **成熟范式**：先完成 SSVEP 与运动想象的特征和已存在模型接口。
4. **扩展范式**：完成视觉图像/目标觉察、注意力和情绪的特征页面与模型契约。
5. **真机闭环**：使用 Windows 诊断包修复问题，两台设备分别通过稳定性验收。
6. **仓库就绪**：补齐 README、安装文档、贡献说明、许可、示例配置、平台锁定策略和 CI；经用户最终确认后再创建或推送公司 GitHub 仓库。

各阶段不能缩减最终目标；后续阶段依赖前一阶段的统一契约和测试证据。

## 13. 完成标准

只有同时满足以下条件才视为项目完成：

- 仓库可在全新 macOS 与 Windows Python 3.12 环境安装；
- 模拟、回放、Neuracle 和 BrainCo 使用同一数据契约；
- 两台真机均有可审计的 Windows 验收证据；
- A 方案任务工作台在常见窗口宽度可用；
- 五类范式均有可信特征页面，模型输出遵守验证门槛；
- 自动测试、回放测试和界面冒烟测试通过；
- 不再依赖本机 `oi-mi` 路径；
- README 和 Windows 真机步骤可由其他同事复现；
- 用户明确批准后才执行公司 GitHub 发布。
