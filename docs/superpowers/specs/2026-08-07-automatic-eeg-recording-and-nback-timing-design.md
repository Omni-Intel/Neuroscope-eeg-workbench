# NeuroScope 自动全导 EEG 保存与 2-back 无缝时序设计

## 1. 目标与范围

本设计同时完成两项已确认修改：

1. 使用“完整采集”预设启动任一范式时，自动为该范式创建独立目录，连续保存全导原始 EEG、刺激/行为事件和会话元数据；范式正常结束、手动停止或按 `Esc` 中止时自动收尾。
2. 将 2-back 改为每个数字固定呈现 1500 ms、数字之间无缝切换、没有空屏或独立反应窗；练习反馈叠加在当前数字下方且不改变节奏，并放大数字显示。

本次不实现把六个范式串成一次自动流程。每次启动一个范式生成一套独立记录。`快速演示` 不自动保存原始 EEG，避免调试产生大量文件；其 2-back 时序仍与完整采集一致。

## 2. 自动记录方案选择

采用 `BDF+ + CSV + JSON`：

- `eeg.bdf`：全导、实际采样率、实际通道顺序的连续脑电数据。
- `events.csv`：逐事件追加的刺激、按键、漏答和协议状态。
- `session.json`：受试者、范式、数据源、通道、样本统计、完成状态和错误信息。

BDF+ 使用 24 位数字范围，适合脑电并可由 MNE、EEGLAB 等工具读取。写入使用 PyEDFlib 的多通道物理采样接口。BDF 按完整数据记录写入；不足最后 1 秒的尾段用零填充，`session.json` 记录 `valid_samples` 和 `padded_samples`，离线读取必须裁剪到 `valid_samples`。

不采用以下方案：

- 结束时一次性写 NPZ：长时全导采集会占用大量内存，异常退出会丢失全部未写数据。
- 只依赖 JellyFish/厂商保存：无法保证平台事件、会话命名和原始 EEG 自动成套。
- 把事件直接作为 BDF+ annotation 的唯一来源：事件写入与 EEG 写入来自不同线程，CSV 以样本索引作为权威对齐记录更容易验证。后续可以把 CSV 转成 BDF annotation，但不属于本次范围。

## 3. 用户界面与文件命名

桌面控制台采集设置增加：

- `受试者编号`：必填，例如 `S01`。只允许字母、数字、短横线和下划线；前后空白会被去除。
- `记录目录`：默认 `<项目目录>/recordings`，允许用户选择其他目录。
- 状态文字：显示“准备记录”“正在写入”“已完成”“已中止”或“保存失败”，并显示实际会话目录。

当预设为“完整采集”并点击“开始刺激”时，立即创建：

```text
recordings/
└── S01/
    └── 20260807-143000_nback_full/
        ├── eeg.inprogress.bdf
        ├── events.csv
        └── session.json
```

范式名使用稳定的 ASCII 标识：`rest`、`nback`、`stroop`、`assr`、`oddball`、`emotion`、`ssvep`、`motor_imagery`、`visual`、`attention`。若同一秒目录已存在，追加递增序号，不覆盖已有文件。

创建目录和打开 BDF 写入器成功后才启动刺激。初始化失败时阻止刺激开始并显示明确错误。正常或可控中止收尾成功后，将 `eeg.inprogress.bdf` 原子重命名为 `eeg.bdf`。

## 4. 数据流与组件边界

### 4.1 SessionRecorder

新增独立 `SessionRecorder`，负责：

- 验证受试者编号和输出目录。
- 根据当前 `SourceMetadata` 初始化全导 BDF+ 头信息。
- 启动后台写盘线程和有界数据队列。
- 接收每个 `EEGChunk`，保持通道顺序和样本顺序不变。
- 逐行追加并刷新事件 CSV。
- 在停止时排空队列、写入尾段、关闭文件并更新 JSON。

记录器不负责刺激逻辑、在线分析或五通道选择。

### 4.2 SessionController

`SessionController` 保留现有 180 秒实时滚动缓冲，并增加可选记录器挂接点。采集线程每收到一个非空 `EEGChunk` 时：

1. 先提交给全导记录器；
2. 再追加到现有实时缓冲；
3. 更新接收统计。

提交只进入后台队列，不在采集线程执行 BDF 磁盘写入。队列容量按至少 10 秒全导数据配置，并持续记录最大积压量。

### 4.3 五通道展示边界

自动保存始终使用数据源返回的全部 EEG 通道。`Fp1/Fpz/Fp2/T7/T8` 或 `T3/T4` 的选择只发生在在线显示、质量卡片和范式分析处，不影响 BDF 内容。

### 4.4 事件写入

每个 `StimulusEvent` 发出时立即追加到 `events.csv`，而不是等待用户手动导出。字段至少包括：

- `monotonic_time`
- `wall_time`
- `eeg_session_sec`
- `eeg_sample_index`
- `paradigm`
- `phase`
- `label`
- `is_practice`
- 完整 JSON `payload`

每行写入后刷新文件缓冲。现有“导出事件 CSV”按钮继续保留，作为额外副本导出功能，不再是唯一保存路径。

## 5. 记录生命周期

### 5.1 启动

1. 确认 EEG 数据源处于运行状态。
2. 若为完整采集，验证受试者编号。
3. 创建本次范式目录并写入初始 `session.json`，状态为 `initializing`。
4. 使用数据源当前实际元数据打开 BDF+ 写入器。
5. 将记录器挂接到 `SessionController`，状态更新为 `recording`。
6. 发出范式 `start` 事件并启动刺激窗口。

因此记录包含刺激开始前极短的写入器预备数据，但不会漏掉 `start` 之后的 EEG。

### 5.2 正常结束

范式达到计划试次数或时长后：

1. 先写入协议 `stop` 事件；
2. 从控制器解除记录器，停止接收新块；
3. 排空后台队列；
4. 尾段不足 1 秒时零填充并记录填充长度；
5. 关闭 BDF、刷新 CSV；
6. 更新 `session.json` 为 `completed`；
7. 将临时 BDF 重命名为最终文件。

### 5.3 手动停止和 Esc

点击“停止刺激”、按 `Esc`、关闭刺激窗口或停止整个采集会话时，使用同一收尾流程，但 `session.json` 状态为 `aborted`，同时记录中止原因。已写数据和事件必须保留。

### 5.4 写盘错误

以下情况不能静默继续：

- 无法创建目录或打开文件；
- 磁盘空间不足或写入异常；
- 记录队列达到容量上限；
- 数据块通道数或元数据在记录中途改变。

初始化阶段错误会阻止刺激开始。运行阶段错误会立即停止刺激、尝试收尾、保留 `.inprogress.bdf` 和错误 JSON，并在主界面显示“保存失败”。不得继续产生看似完整的实验记录。

## 6. BDF+ 数据约束

- 使用实际 `sfreq`，要求为正整数采样率；不满足时拒绝 BDF 自动记录并显示原因。
- 每个 EEG 通道写入实际名称、单位和采样率。
- BDF 标签最长 16 个字符；过长或重复的通道名必须生成唯一短标签，原始名称到 BDF 标签的完整映射写入 `session.json`，不能静默截断成重复标签。
- 当前实时源的物理单位为 `uV`；遇到非 `uV` 通道时保留元数据单位并在 JSON 中记录。
- 默认物理范围固定为 `-262144` 至 `262143` 单位值，BDF 数字范围为 `-8388608` 至 `8388607`，约提供 0.0625 单位量化步长。
- 写入前检查 NaN、Inf 和超出物理范围的样本。非有限值或削顶数量写入 JSON；非有限值替换为零，超范围值裁剪，但界面必须显示质量警告。
- BDF 最后一个数据记录可能包含填充样本；离线工具以 `valid_samples` 裁剪。
- PyEDFlib 不可用时，“完整采集”必须在刺激开始前报错并给出安装命令，不能降级为只保存事件。

## 7. session.json

`session.json` 至少包含：

- `schema_version`
- `participant_id`
- `paradigm`、`preset`、`protocol_version`
- `source_id`、`source_type`
- `sfreq`、`channel_names`、`channel_types`、`channel_units`
- `started_at`、`ended_at`
- `status`：`initializing`、`recording`、`completed`、`aborted` 或 `error`
- `stop_reason`
- `valid_samples`、`padded_samples`、`chunks_written`
- `events_written`
- `nonfinite_samples`、`clipped_samples`
- `max_queue_depth`
- `timing_status`
- NeuroScope 与 Python 版本
- 保存错误信息（如有）

JSON 更新通过“写临时文件再原子替换”完成，避免中途留下半截 JSON。

## 8. 2-back 新时序

### 8.1 呈现

- 每个上下文数字、练习数字和正式数字均完整显示 1500 ms。
- 一个数字到时后立即切换到下一个数字，不出现空屏、注视点或独立反应窗。
- 数字序列使用固定绝对时间表计算当前试次，避免逐次定时误差累积。
- 练习结束后保留一个明确的“正式开始”提示页；正式数字序列开始后内部完全无缝。
- 2-back 数字使用专门绘制函数，字号显著大于通用中央文字；按窗口尺寸自适应，目标字号约为 96 px，确保第二屏远距离可见。

### 8.2 响应与反馈

- 一致按 `J`，不一致按 `F`。
- 响应窗与数字呈现完全重合，为 0–1500 ms。
- 每个 trial 只接受第一次有效按键，之后按键忽略。
- 正式试次不显示反馈。
- 练习试次按键后立即在当前数字下方叠加“正确”或“错误”，反馈只持续到该 trial 的固定结束时刻，不延长 1500 ms。
- 练习和正式漏答均在 1500 ms 边界计错并产生 `omission` 事件。练习漏答不把提示叠加到下一数字，避免干扰下一 trial。

### 8.3 计分

原有正式统计继续使用：一致正确率、不一致正确率、总体正确率、平衡正确率、两类正确试次中位反应时和漏答。删除 2000 ms 反应时门限，改为 1500 ms。

## 9. 自动化测试

### 9.1 记录器

- 启动完整范式立即创建受试者/会话目录和三个文件。
- 快速演示不自动创建原始记录。
- 模拟多通道、不同块大小的数据流写入后，BDF 读回的通道名、采样率、有效样本数和数值在量化误差内一致。
- 最后不足 1 秒的样本正确填充，JSON 的 `valid_samples` 和 `padded_samples` 正确。
- 正常停止得到 `completed` 和最终 `eeg.bdf`。
- `Esc`、停止采集和窗口关闭得到 `aborted`，已有数据仍可读取。
- 目录重名不覆盖。
- 非法受试者编号、目录不可写、通道改变、队列溢出和磁盘写入异常均产生明确失败状态。
- 固定范式的 BDF 仍包含全导数据，五通道选择只影响在线分析。

### 9.2 事件

- `start`、刺激、响应、漏答、`stop` 全部自动写入 CSV。
- CSV 中 `eeg_sample_index` 单调不减且正式/练习标记正确。
- 开始下一范式不会删除上一范式目录或事件文件。

### 9.3 2-back

- 每个上下文和评分 trial 的计划时长均为 1500 ms。
- 相邻数字之间没有 `blank` 或独立 `response_window` 事件。
- 1499 ms 内按键有效，1500 ms 及之后归入下一 trial 或忽略，不能记入上一 trial。
- 练习反馈不会改变下一数字的计划开始时间。
- 正式阶段不产生反馈阶段。
- 漏答计错并记录，但不在下一数字上显示上一 trial 反馈。
- 新的数字绘制字号大于通用中央提示字号。

## 10. 手工验收

1. 连接模拟源，输入 `TEST01`，选择完整 2-back 并开始。
2. 确认目录在刺激出现前创建，数字每 1500 ms 无缝切换且字号足够大。
3. 练习中分别做正确和错误响应，确认反馈叠加且不改变节奏。
4. 正式阶段确认没有反馈和空屏。
5. 中途按 `Esc`，确认 BDF 可读、CSV 有事件、JSON 为 `aborted`。
6. 再完整跑一个快速短范式，确认快速演示不自动保存原始数据。
7. 用博睿康真机运行短测试，确认 BDF 保存全导，在线页面仍只显示目标五通道。
8. 核对 BDF 有效样本数、CSV 最大样本索引和 JSON 统计一致。

## 11. 完成标准

- 完整采集的每个范式在开始时自动建档并保存独立全导 BDF、事件 CSV 和会话 JSON。
- 正常结束和可控中止均自动关闭文件，不需要手动导出才能保留事件。
- 保存失败时立即阻止或中止实验，不能静默丢数据。
- 2-back 数字持续 1500 ms、全程可响应、相邻数字无缝衔接。
- 练习反馈只叠加在当前数字下方，不增加时间窗；正式阶段无反馈。
- 数字明显放大，原有 J/F 计分和平衡统计保持正确。
- 模拟、NPZ 回放、博睿康和 BrainCo 采集链路的既有测试继续通过。
