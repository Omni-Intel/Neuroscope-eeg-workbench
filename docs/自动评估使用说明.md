# NeuroScope 安装与实验报告使用指南

NeuroScope 用于连接脑电设备、运行实验、保存数据并生成 Word 评估报告。支持 Neuracle、BrainCo、公司 OmniBCI SDK 和 EMOTIV 外部录制；也提供模拟数据源与回放。保留十个范式，其中 **SSVEP 提供专项响应与分类分析，四条件运动想象用于采集后续训练数据**。MI 保留通用质量报告，任务响应与分类栏目标注“待更改／模型待接入”。

报告描述一段记录的数据可用性、信号干扰和任务相关表现，不直接给设备排名或被试能力评分。无需个体化训练，报告不生成 HTML。

## 1. 安装与启动

准备 Windows x64 电脑、可联网的安装环境，以及本仓库完整源码。使用 **uv、Python 3.12 和仓库内 `.venv`**，不使用 conda 或旧 `.venv312`。

1. 按 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/) 安装 uv，重新打开 PowerShell，运行 `uv --version` 确认可用。
2. 在仓库根目录（包含 `setup-workbench.ps1` 的文件夹）打开 PowerShell。
3. 公司设备所需 wheel 不随 Git 分发。按 [SDK 安装说明](../vendor_sdk/omnibci/INSTALL.md) 下载正式版 `omnibci-0.2.0-cp311-abi3-win_amd64.whl`，放到 `vendor_sdk/omnibci/`；换机部署时保留校验文件和许可证。
4. 安装并启动：

```powershell
.\setup-workbench.ps1
.\start-neuroscope-desktop.bat
```

安装脚本按 `uv.lock` 准备 Python 3.12 环境、桌面依赖及设备 SDK，并检查依赖一致性。若 PowerShell 提示禁止运行脚本，可在当前终端执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup-workbench.ps1
```

没有公司 SDK、只需先测试模拟或其他设备时，执行 ` .\setup-workbench.ps1 -SkipOmni`；不使用 BrainCo 时可同时加 `-SkipBrainCo`。以后要使用被跳过的设备，准备好材料后重新运行完整安装命令。

安装完成后，日常可直接双击 **启动-NeuroScope桌面控制台.bat**。程序从本仓库源码启动，不依赖同级 template、demo、视频任务或外部 oi-mi 工程。更新源码后关闭程序，重新运行安装脚本，再启动；不要自行升级锁定的依赖。

## 2. 第一次使用：先跑模拟流程

| 顺序 | 在哪里操作 | 操作及预期结果 |
| --- | --- | --- |
| 1 | 实验准备 | 填写 8 位被试编号、数据保存目录，选择模拟数据源。测试编号不要当作正式平台身份。 |
| 2 | 范式设置／实验准备 | 选择 SSVEP 或运动想象，检查对应实验信息。SSVEP 自动使用 `SSVEP-20261030`，MI 使用 `MI-20261030`；这些是本地预置身份，正式使用前仍需核对平台信息。 |
| 3 | 实验准备 | 点击“连接并检查数据”，等待“已接收数据”；到采集监控确认波形。连接检查本身不保存正式实验。 |
| 4 | 范式设置 | 选择“完整采集”。流程测试可设 SSVEP 8 次或 MI 3 次，并缩短基线；点击“保存实验设置”。 |
| 5 | 范式设置 | 点击“开始实验”，进入全屏说明。准备页按空格继续，按提示完成练习、静息与正式试次。 |
| 6 | 实验结束 | 正常完成后自动封存并处理 EDF 和报告；空格返回控制台。提前结束可按 Esc 或“停止实验”，已采数据保留并标记中止。 |
| 7 | 记录与报告 | 查看 EDF 交付与报告的各自状态，打开 Word。失败时先看原因，补齐信息后使用“重试 EDF 交付与报告”。 |

**快速演示不保存记录，也不生成报告；完整采集才用于上述完整流程。**模拟结果用于检查软件功能，不代表真实设备性能。

## 3. 连接真实设备

选择设备后填写其专属参数，再执行连接；仅选择设备不会自动开始连接。

| 设备 | 连接前准备 | 操作与成功依据 |
| --- | --- | --- |
| Neuracle | 在厂商软件开启 JellyFish TCP 数据转发，核对地址、端口、采样率及 EEG 通道数；EEG 数不含 TRG | 填写转发参数，点击“连接并检查数据”，以实际收到样本为依据 |
| BrainCo | 设备与电脑处于可互通网络，已安装 BrainCo 依赖 | 勾选自动发现后点击连接；也可填写实际地址和端口。收到样本后显示“已接收数据”及连接信息 |
| 公司 OmniBCI | 已安装部署材料中的 SDK，确认串口或 BLE 连接方式 | 点击“扫描公司设备”，选择设备地址后连接；检查实际样本和波形 |
| EMOTIV | 在 EmotivPRO 中连接设备并录制，核对 Marker 配对串口 | 扫描并选择 Marker 串口，准备外部录制并人工确认；结束后导出并关联对应 EDF，再提供事件对齐依据 |

EMOTIV 串口扫描检查的是标记通道，人工确认不等于程序已验证 EEG 收样。外部 EDF 未关联或未对齐时，不计算专项任务指标。

连接后可点击“保存连接配置”；地址、端口和配置路径等按设备分别保存，下次仍需重新连接检查。出现“等待数据”“数据暂未更新”或异常提示时，先排查设备与转发设置。

正式采集还需核对：

- **实验信息**：通过“建立 / 编辑实验信息”维护名称、唯一名称和简介；保存在 `experiments/<范式>/metadata.toml`。唯一名称是稳定的实验身份，不随每次采集日期变化。
- **设备配置**：按实际通道顺序填写电极名称、单位、参考、工频等，再确认配置。参考 [设备配置示例](../profiles/device-profile.example.json)，不要直接把示例当作厂商规格。
- **EDF 范围**：本机导出要求 `physical_min`、`physical_max` 覆盖所有保存通道，并提供 `range_evidence`。这些值来自设备依据，不取本次观测极值。分析削顶所需的 `adc_rails_uv` 是另一个硬件依据，不能自动用 EDF 编码范围替代。

SSVEP 专项分析需要已确认的枕区电极及至少 180 Hz 采样率。四条件 MI 完整保存设备通道，不以 C3、C4 是否齐全限制采集；通用特征要求已确认微伏 EEG 通道且至少 100 Hz。旧三条件 MI 分析仍要求 C3、C4。设备接口可用不等于该型号已通过现场验收。

## 4. 实验流程与默认参数

每种范式独立执行：**说明与指导 → 练习 → 睁眼静息 → 闭眼准备 → 闭眼静息 → 睁眼恢复 → 正式分组**。准备和组间等待使用空格继续；计时阶段不能用空格跳过。闭眼阶段屏幕显示倒计时，不播放声音提示；主试与被试事先约定无声的睁眼提醒方式，在屏幕出现“请睁眼”后提醒。

| 参数 | SSVEP | 运动想象 |
| --- | --- | --- |
| 条件 | 九宫格外围八个方块，默认每次仅提示目标闪烁，其余保持暗色；固定 8–15 Hz、间隔 1 Hz | 左手 → 右手 → 双脚（双腿）→ 舌头，固定循环 |
| 正式试次／每组 | 80／40，各条件等量 | 120／40，每条件共 30 次 |
| 练习 | 每条件 1 次 | 每条件 2 次 |
| 单试次 | 中央注视 1.5 秒 → 红框提示 1 秒 → 目标常亮定位 1 秒 → 闪烁 5 秒 → 休息 4 秒 | 准备 2 秒 → 提示 1 秒 → 想象 4 秒 → 休息 2 秒 |
| 独立静息 | 睁眼 60 秒、闭眼准备 10 秒、闭眼 60 秒、睁眼恢复 10 秒 | 相同，每次范式重新采集 |
| 组间最短休息 | 60 秒，之后按空格继续 | 相同 |
| 默认最短总时长 | 约 21 分 40 秒 | 约 23 分 32 秒 |

SSVEP 每组按 **8→9→10→11→12→13→14→15 Hz** 循环，默认每次仅提示目标闪烁，其余七块保持暗色；在“刺激显示 → 闪烁方式”可选择八目标同时闪烁。总试次和每组试次须为 8 的倍数。默认 80 次即每频率 10 次；固定顺序可能混入时间或疲劳影响，设备比较时应保持相同设置及闪烁模式。

刷新调度及验证边界见 [SSVEP 显示时序说明](SSVEP显示时序说明.md)。时序异常只记录，不自动中止实验或弹窗。新版单目标模式使用 `guided-assessment-v5` 和 `assessment-v1.6.0`；下文 `assessment-v1.4.0` 对应保留的八目标同时闪烁模式，旧记录保留原协议。

MI 总试次与每组试次须为 4 的倍数。想象对应部位运动的感觉，不做实际运动；屏幕指导解释四种条件。条件代码 1／2／3／4 对应左手／右手／双脚／舌头，提示时发送对应 Marker，想象起止另有阶段事件。事件保存练习标记、组号、正式试次索引和提示标签。固定顺序会引入时间相关性；后续训练与验证应分开会话或分组，避免相邻片段泄漏。

“刺激显示”页填写屏幕对角线、方块边长及实测观看距离。请求边长默认 3 cm；未填写屏幕尺寸时使用屏幕短边的 20%，不声称具有确定的厘米尺寸；过大尺寸会限制到短边的 25% 以避免重叠。频率与黑白方波方法依据 Nakanishi 等（2014），项目的时长、布局和试次数调整见 [八目标依据与设置](SSVEP八目标依据与设置.md)。

显示配置、实际像素外框和计划顺序保存在 `run.json` 的 `protocol_start_payload` 中，实际执行顺序以 `events.jsonl` 为准。注视、提示、定位、闪烁、休息均记录软件事件；硬件标记沿用现有注视／闪烁／结束编码，提示与定位不新增硬件码。刷新率与帧事件不能替代光电时序验证。旧记录仍按保存的旧版协议分析。

SSVEP／MI 使用 `perf_counter` 高精度时钟推进刺激，分别记录定时回调和 Qt 画面交换间隔。报告仅统计同一正式试次、同一阶段内的间隔，并标出超过预期周期 1.5 倍的长间隔。画面交换回调不能证明物理闪烁频率；旧记录缺少这些证据时，重新生成报告也无法补回。

总时长不含阅读、按键等待。参数可在“实验流程与参数”调整，默认值标在控件旁；总试次与每组试次须为条件数的整数倍。开始后参数锁定，报告读取该次保存的配置。条件按固定等量轮换，练习不计分。连续进行两个范式时，各自保留独立静息、记录和报告。

## 5. 报告怎么看：指标与计算来源

SSVEP／MI 的 Word 按“基本信息与完成情况 → 信号质量、接触与通用特征 → 当前范式响应 → 固定算法与结论”组织，保留关键证据图和必要对照表，不按固定页数删减。异常通道、分组或测量条目较多时会增加页数。逐试次数据、扩展复杂度及完整分类统计保存于同次分析目录。

每个主题就近安排结果表、证据图和解释。SSVEP 的逐试次目标频带平均 SNR 与平均频谱的逐频点 SNR 曲线不是同一统计量；MI 功率表采用完整分析窗，频谱图采用 1 秒 Welch 分段，整窗 ERD、滑窗 ERD 和时频 dB 也分别说明。侧化表同时列出 C3−C4 与对侧−同侧，注明左手条件的符号转换；混淆矩阵对应“全部已观察”试次。

**MI 适用范围：**上述 MI 响应图表和下表中的旧 MI 算法仅用于已有三条件记录。新四条件记录不运行旧算法，任务响应和分类栏目只显示“待更改／待接入”；通用质量、实际阻抗、通用特征正常生成。完成表按四条件列计划、观察、完成和数据完整次数，数据完整不等于想象有效；核查代码为 [mi_collection.py](../neuroscope_eeg/analysis/mi_collection.py)。

| 顺序／位置 | 指标及含义 | 分析代码来源 |
| --- | --- | --- |
| 1 完成情况 | 计划、完成、可分析／观察、筛查后／可分析试次；程序完成不等于被试实际执行已验证 | [response_evidence.py](../neuroscope_eeg/analysis/response_evidence.py)：`retention` |
| 2 通用质量 | 有效样本、序号与时间间隔；RMS、峰峰值、平直与大幅值窗、工频比例。正文给通道范围、异常通道、分段质量表及功率谱图，不展示全程筛查图；明细保留逐通道与逐窗结果，不将时间间隔直接当丢包 | [assessment.py](../neuroscope_eeg/analysis/assessment.py)：`assess`、`channel_quality` |
| 3 接触质量 | 阻抗或厂商接触等级，保留测量时间与单位；无测量则不可用，CQ/EQ 不换算为 kΩ | [impedance.py](../neuroscope_eeg/io/impedance.py)、[assessment.py](../neuroscope_eeg/analysis/assessment.py) |
| 4 通用特征 | 谱熵描述频谱分散程度，样本熵描述不规则性，Hjorth mobility 描述变化特征，谱斜率描述 2–40 Hz 频谱倾斜；均非设备合格线 | [general_features.py](../neuroscope_eeg/analysis/general_features.py)：`feature_values`、`assess_features`；使用 mne-features、antropy 同源库 |
| 5 SSVEP 响应 | 基频与二／三次谐波 SNR、睁眼基线功率对照、条件频谱／SNR 图、逐通道响应及分组变化图；SNR 为目标频带与邻近背景功率比的 10log10，共享谐波不单独归属某目标 | [task_assessment.py](../neuroscope_eeg/analysis/task_assessment.py)：`local_snr`；[response_evidence.py](../neuroscope_eeg/analysis/response_evidence.py)：`add_ssvep`、`prepare_resting` |
| 6 MI 响应 | μ 8–13 Hz／β 13–30 Hz 的基线与任务功率、ERD、对侧−同侧变化、恢复期 β；正文含 ERD 时程、条件频谱、时频、侧化及分组图；ERD=100×(任务−试次基线)/试次基线，负值表示下降 | [task_assessment.py](../neuroscope_eeg/analysis/task_assessment.py)：`mi_metrics`；[response_evidence.py](../neuroscope_eeg/analysis/response_evidence.py)：`add_mi` |
| 7 固定算法 | SSVEP 固定 FBCCA，无个人模板；MI 固定 μ 频带 C3−C4 dB 差 >0.6 判左手、<−0.6 判右手，其他未判定，静息不计入二分类 | [task_assessment.py](../neuroscope_eeg/analysis/task_assessment.py)：`fbcca`、`mi_metrics` |
| 8 分类与区间 | 准确率及 Wilson 区间、平衡准确率（各类 Recall 均值）、判定覆盖率。全部已观察、可分析及筛查后并列；未判定按未正确计，不能只看已判定子集；正文保留混淆矩阵 | [task_assessment.py](../neuroscope_eeg/analysis/task_assessment.py)：`classification_summary`、`wilson` |
| 9 补充明细 | Hjorth activity（variance）／complexity、近似熵、SVD 熵及 Fisher 信息、Hurst、Higuchi／Katz 分形、DFA、Lempel–Ziv；任务的逐试次与逐通道响应明细；完整 Precision／Recall／F1 等分类统计 | [general_features.py](../neuroscope_eeg/analysis/general_features.py)、[response_evidence.py](../neuroscope_eeg/analysis/response_evidence.py)、[task_assessment.py](../neuroscope_eeg/analysis/task_assessment.py) |

**通用特征计算条件：**保留采集参考，选择已确认微伏 EEG 分析电极；在睁眼、闭眼、正式实验各自连续区段内切完整 4 秒窗，不拼接暂停。排除无效／非有限样本、断点、异常幅值和已确认量程触及窗。独立做 1–40 Hz 四阶零相位滤波并重采样到 250 Hz，不陷波；原始采样率不足 100 Hz 则不计算。每区段每通道最多均匀选 30 个合格窗，先取通道内中位数，再取跨通道中位数。正式区段包含提示、任务与试次内休息，不能将该汇总解释为纯任务响应。

这部分参考 `8.21/nback_eeg_toolkit/vendored/epoch_feature_extraction.py` 与 `step3_epoch_metrics.py`。库默认参数、版本和抽样数量记录在 `assessment.json` 与明细中。原 N-back 使用 1–80 Hz、Fpz 重参考及负荷条件，这里分析条件不同，不直接比较数值。谱斜率包含振荡峰，不是分离出的非周期指数；复杂度不解释为专注、放松或设备分数。N-back 的行为评分、负荷比值和训练模型不迁移。

SSVEP／MI 专项算法独立使用原任务数据，不使用通用特征的滤波结果。响应均值的 95% 区间采用固定种子 2000 次试次自助法，少于 3 次不估计；仅作本次描述。筛查后不代表完全没有伪迹。

MI 筛查前后使用相同试次时，ERD 时程只画一组曲线并注明两者一致；不满足区间估计条件时，不显示区间阴影。普通模拟数据源不随刺激生成任务响应，模拟报告用于检查流程，不能据其分类准确率评价设备。

[compact_report.py](../neuroscope_eeg/reports/compact_report.py) 负责正文，[generate.py](../neuroscope_eeg/reports/generate.py) 负责导出和版本管理。八分类 SSVEP 使用 `assessment-v1.4.0`，四条件 MI 采集核查使用 `assessment-v1.5.0`，旧记录保留原分析口径。八分类的 SNR 背景排除范围见 [八目标依据与设置](SSVEP八目标依据与设置.md)，不要与旧四分类 SNR 直接比较。安装脚本会安装已锁定的通用特征依赖；升级后应重新执行安装脚本。其他范式保留原有通用报告方式。

## 6. 文件保存在哪里

你选择的是保存根目录，每次完整实验拥有独立 UUID：

```text
保存根目录/
├─ data/<unique_name>/recording-<UUID>/
│  ├─ dataset_description.json、participants.tsv、.bidsignore、README
│  └─ sub-<8位编号>/ses-<UUID>/
│     ├─ session.json
│     └─ eeg/
│        ├─ *_eeg.edf、*_eeg.json
│        └─ *_channels.tsv、*_events.tsv、*_events.json
├─ Reports/<unique_name>/recording-<UUID>/<生成版本>/
│  └─ <与报告题目一致的名称>.docx
└─ Records/recording-<UUID>/
   ├─ raw/、events.jsonl、behavior.csv
   ├─ run.json、device.json、config.json、provenance.json
   ├─ external/、impedance/、delivery/        按需关联与交付状态
   └─ analysis/<生成版本>/                  JSON、CSV、图像与状态
```

模拟／回放的交付目录使用 `simulation_<unique_name>`。重新生成报告会保留独立版本，`Records/.../analysis/latest.json` 指向最近成功的报告。EDF 与报告分别处理：报告生成成功不代表 EDF 已通过 BIDS 校验，也不代表数据已上传或 EEGQC 已入库。

## 7. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 启动找不到 Python／依赖 | 在仓库根目录重新执行安装脚本，确认 `.venv/Scripts/python.exe` 存在 |
| 连接后没有波形 | 查看连接错误和样本计数，核对设备供电、网络、转发和采样配置；不要仅凭“接口已启动”开始实验 |
| 实验结束没有记录／报告 | 检查是否使用“快速演示”；完整采集后到“记录与报告”查看后台状态 |
| 有报告但任务指标不可用 | 按原因检查电极、微伏单位、采样率、阶段完整性及事件对齐；不是自动判定设备差 |
| EMOTIV 报告等待 EDF | 使用“导入并关联 EMOTIV EDF（自动评估）”，绑定本次记录，再补充对齐依据；重试按钮不会代替 EDF 导入 |
| 没有阻抗结果 | 在记录与报告中导入本次测量凭据；参考 [阻抗导入示例](../profiles/impedance-import.example.json)，不能用历史或另一设备测量代替 |
| EDF 导出失败但 Word 已生成 | 检查交付错误，补齐实际量程、单位等依据，再重试；不要修改原始信号以通过校验 |

真实设备部署、实验身份与量程配置的详细约定见 [规范实施与使用](规范实施与使用.md)。首次使用某型号时，应先完成实际收样、断连恢复、通道单位和事件同步检查，再安排正式实验。
